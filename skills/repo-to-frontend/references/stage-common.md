# 阶段共享约束

阶段Skill中的共享参考文件名（例如project-grounding.md）均指本目录中的对应文件，工具/素材路径以repo-to-frontend根目录解析；不要误从阶段入口目录寻找scripts或assets。引用内的流程只应用于本次已选择阶段，不因读到后续章节就执行后续工作。

你是这条流水线的执行者。交付的是**目标仓库的解读文稿、设计图与对应前端**，不是运行这条流水线的管理平台。复用 Codex 已有工具，不为使用本 Skill 新建服务器、账号系统、任务控制台或通用分析产品。

## 确定本次范围

- 输入可为 GitHub 地址或本地仓库。沿用用户指定的语言、受众、技术栈、输出目录和执行阶段。未指定时：中文、面向有基本编程知识的读者、做解释型页面；已有前端沿用其栈，独立视觉样例默认自包含 HTML/CSS/JS，复杂应用才考虑 React + Vite。
- 只执行用户选择的阶段，复用已有且有效的上游产物。组合执行按依赖顺序推进；缺少必需输入先检查已有材料，不自动扩大到未选择阶段。
- 用户要求忽略已有前端时，这一边界从解析阶段起生效：不读取其HTML/CSS/JS、截图和设计稿，仅从允许材料提炼事实；后来明确授权审查时才改变此范围。
- 独立图片复刻同样适用，不要求先有仓库、财务模型或解释型内容。用户的项目是案例，不把它的布局、单位、字号或节点数固化为通用规则。用户要求优化Skill时，交付可复用规则/工具与独立验证，不以修改案例网页代替Skill迭代。
- Skill优化请求先读 [references/skill-transfer-validation.md](skill-transfer-validation.md)，将案例失败转成机制改动和跨项目实验；不自动把整套案例重做设为主完成条件。
- 审查/比较请求只取证与建议；明确要求修改Skill或实现时才修改相应目标。Skill改动、案例改动、安装部署和验证分别记录。
- 用户授权自主决策且目标明确时，用苏格拉底式自检代替逐项追问：它解决什么问题？关键证据是什么？哪一步支撑下一步？什么证据会推翻我的理解？缺少目标仓库、必要权限、不可替代能力或影响承诺的关键契约时指出受影响阶段的阻塞；其余可执行部分继续。目标歧义会改变交付时仅澄清该差异，不重复询问已明确意图。
- 默认在工作区 `outputs/repo-to-frontend/<repo-name>/` 保存结果，不改目标仓库业务代码，除非用户要求集成。保留既有工作；范围纠偏不意味着可以删除旧代码。


先确定阅读深度：概览、机制解释、逐步计算拆解。用户要求“每一步尽可能详尽”“计算过程”或指出过简时，使用逐步计算拆解，并先读 [references/deep-decomposition.md](deep-decomposition.md)。不得用代表性单步、更多同层卡片或图片数量替代全部指定步骤的机制覆盖。未指定深度时按用户理解目标判断，不默认把复杂分析系统缩成宣传式导览页。

## 按需选用开源工具

所选阶段出现具体能力缺口（符号/关系导航、叙事、客户端生成、网络测试或视觉验收），或用户要求重新调研时，读取 [工具路由](github-toolkit.md) 的对应条目。先检查现有能力/依赖，记录选择与实际运行结果；不是只有源码阅读不足才可用工具，也不自动安装整个清单。

## 可选独立审查

`independentReview.enabled`默认false，与图片审核独立。同任务设置从run-state及用户决定继承，独立调用阶段不复位。开启或用户本次明确要求子代理审查时，读取[独立审查协议](independent-review.md)：每个已选阶段自验后、交接前以新上下文只读审查，只返回结论和证据定位。关闭不免除自检和测试；“独立验收”名称本身不意味着派发代理。
