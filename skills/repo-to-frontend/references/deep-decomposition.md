# 深度拆解：读者可以复算，而不只是浏览

## 深度合同与覆盖账本

先枚举用户指定范围内的每一个业务步骤和其独立变换，再确定图数。保存step-ledger（JSON或等效结构）：step id、问题、子步骤、输入字段/单位/期间/归属、公式或判定规则、符号/行号/文件指纹、输出、下游用途、失败条件、图形类型、交互及审核状态。

逐项展开到读者能代入数字复算，或跟着证据判断知道为何支持/不支持为止。包装函数不必逐行翻译，但不得跳过会改变结果的归属选择、期初期末、分母限制、窗口连续性、替代/去重、样本门禁和证据传播。列出已覆盖/未知/不适用，不把未读当不适用。

源码目录不等于机制：分析器若调用renderer-neutral display/adapter/enrichment层，继续追踪派生计算与数据集定义；只读入口和一个代表性函数不足以覆盖其余步骤。遗留指标编号不一致时，以正式步骤与公式语义映射，不据字符串前缀强行归属。

## 从结构化模型到图集

借鉴typed diagram IR：稳定节点、明确关系类型、证据定位、精确数据和计算分离于坐标与视觉风格。关系只能来自已记录事实；点击高亮只是已建模依赖，不宣称运行时影响分析。源码指纹/定位核验也不自动证明解释正确。

总览容纳主要路径，细节进入逐步骤图和计算/证据结果态；“主图少节点”仅是局部可读性约束，不能删掉整套范围。根据独立问题选择图形：映射/决策、同比序列、分部构成、瀑布、因子树、样本点图、事件时间线、证据矩阵。不要为不同机制重复同一个通用KPI面板。非数值步骤不能捏造总分、概率或伪精确指标。

每步的可视化、公式代入、结果和下游关联都必须可达；不能只有一步真钻取，其余换标题。关键额外布局要生成结果态参考，同布局换数值可由结构化数据契约覆盖。图像只是视觉设计，不执行计算。

## 计算与交互

生图prompt直接嵌入所选子步骤、精确输入、公式、中间值、结果、边界和按钮动作。明确该图首屏展示哪些子问题，以及剩余细节在HTML哪里展开；不得为了大标题/留白删除已承诺计算。

HTML共用单一数值模型：图形、表格、公式、证据及筛选从相同数据派生。参数编辑必须真实重算，并标明“控制其他变量的算式演示”而非业务预测。每个结果能展示代入与来源；数字可以合成，规则仍有源码依据。只实现教程子集时逐项列明其范围，不冒充运行了原系统。

缺失不当0；负/零分母按源码处理；跨期/合并/归母/分部范围不得混算。不能将多个已披露端点的差称为完整调节残差。证据/治理步骤显示查询范围、支持/反证/未知，不把未查当无记录。

## 验收

覆盖检查来自源码步骤清单，而非已生成文件清单。逐步骤核验输入→公式/判定→结果→图形→证据→下一步。数值测试独立手算预期值，不从被测函数复制期望；至少覆盖实际相关的缺值、非正分母、断年、口径不匹配、替代重复计入和样本不足。

先验证内容深度和计算，再分开验证结构、浏览器行为、图像保真。页面能点击、13张图存在或格式验证成功，都不是步骤逻辑充分的证明。未通过项不得靠减少范围或删除门禁变绿。
