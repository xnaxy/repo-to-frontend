# 从“看起来可点击”到可验证的结果

静态图片不执行交互。生图模型负责把控件、状态和结果面板表现清楚；Codex负责实现并测试。不能声称图片模型已经验证按钮行为。

仓库任务先使用 [project-grounding.md](project-grounding.md) 的能力合同。每个I项关联B能力与证据，注明真实调用/静态解释/本地模拟；真实调用补method/path、请求响应字段、权限与开关、异步状态及错误。UI动作成功不能早于后端成功；没有依据的取消、导出或进度不因图片出现就承诺。轮询停止、切换对象后的旧响应处理按实际能力设计，未运行真实服务不得把mock通过记成联调通过。

在生图前建立 `interaction-contract.json`，每项包含：稳定id、控件文案、所在图/状态、触发方式、前置条件、改变的状态、结果区域与确切内容、目标图/状态、返回或关闭规则、键盘操作、可观察验收。显示但不可操作的元素另外列为静态；禁用控件说明条件和原因，不伪造“已下载/已分析”的成功反馈。

示例：I03“查看依据”位于cash/default；点击或Enter后，打开cash/evidence面板，显示当前企业+年度+指标对应的公式、输入值、单位、来源定位；关闭或Escape返回cash/default，保留年度/指标并恢复触发按钮焦点。年度改变时证据必须一起更新，或明确关闭面板；不能保留上一年的来源。

严格复刻还要记录每个参考状态的同时可见区域、modal或非modal、遮罩/模糊、选中项、焦点、滚动与容器占比。常驻侧栏不能仅因为也能“查看详情”就改成遮挡正文的模态；两个同时展示的演算情景不能合并成互斥选项。用实际控件/面板探针核对状态，不手填与参考相同的值。参考未提供的状态只能按已确认行为实现，不能称其视觉已证明1:1。

## 把契约送进每张生图prompt

- 写明当前状态、每个可点击控件的准确标签、点击后的具体结果与目标状态。生成默认态时也包含行为说明，不把外部契约当作模型已见的上下文。
- 要求模型用可辨识的按钮样式呈现可点击项，静态数字/装饰不伪装控件；图旁可用简洁交互注释或单独注释区域说明动作→结果，标明这些注释是设计说明、是否进入最终网页。不要在正式业务正文塞入冗长实现指南。
- 会明显改变布局的抽屉、弹窗、钻取页至少提供关键结果态参考；同一布局的筛选值变更可用共享数据/契约覆盖，不强制为每个值付费生图。默认态/结果态分别存文件并互相引用，不能只做按钮外观。
- 多图共享企业、年度、指标和证据ID、URL或视图标识；声明跨图携带哪些状态、何时重置、直接打开如何初始化以及返回来源。语义关系图和页面导航图分别记录，避免把导航箭头解释成程序调用。

详情导航需实际传递所选对象/指标和对应输入，不能所有链接都显示同一默认详情。按运行环境选择最小状态传递方案：同页状态、路由参数或已有状态层均可；离线文件不能假设同源存储或服务器可用。外部参数做白名单与数值校验，未知指标不降为一个看似成功的默认结果。返回分别验输入、面板状态和触发焦点；审核外壳中的内部跳转也要同步参考图，但该同步本身不证明数据状态与原图等价。

多图整合先按“页面/模块作用域 + 控件语义”核对目标，不用菜单索引或可见编号直接推算文件名。相同编号可能代表不同模块，同一图也可能保留重复编号；显示文字与路由ID分离，逐条显式映射有证据的目标。参考里某个子模块没有对应交付页时保留明确限制，可另设不冒充原控件的整套审核导航，不能链接到名称不同的同号页面来通过可达性测试。

显示格式化不能改写原始输入；尤其不能把非零小数舍入成零后再用于详情或返回计算。主页面和详情共用或验证同一计算定义，并检查中间量/结果有限，不只检查输入。引入URL或持久状态后，重新检验“恢复默认”：刷新可能只会重载携带状态，必须按契约显式清除或替换相关状态。使用一次小于显示精度的非零输入与一次超出中间运算范围的输入检验往返，不将通过普通整数案例推广成所有输入有效。

## 按交互逐项验收

输入可编辑时，先为每个字段列出可见依赖：输入展示、公式代入、摘要、表格单元格、图表标记、校验结论及证据预览。一次提交先校验完整输入，再从同一状态更新全部依赖；不能仅更新最醒目的结果卡。保留不受影响的对照值，并明确它不是派生结果。空值、零分母和非有限数分别处理，失败提交不得留下半新半旧的结果。

测试至少一次会改变校验结论的输入，而不是只改不影响结果的装饰值；逐个核对依赖，再恢复原始输入。数据恢复、图形恢复和完整界面状态恢复分别检查：数值相同但标签选中、抽屉、焦点不同，不是同一参考状态。原图的非一致图形尺度按skill-transfer-validation.md处理，编辑态不能借用参考态的像素一致结论。

联动一致不等于计算正确。另查分项合计、正负符号、替代/去重及固定对照与派生量；只有图片而无完整计算依据时，明确模拟常量与未实现机制，不把原图矛盾包装成业务模型。固定参考显示与可编辑状态的格式合同分开：编辑态代入精度必须足以解释结果，残差判定容差需可见，不让“显示为零但结论失败”无解释出现。加入小数边界反例；成功、失败提交和恢复都核对独立列出的输出清单，而不只检查一个公式面板。

对每个约定交互实际触发，核对结果内容而非仅“事件触发了”。包含跨图往返、筛选后来源一致、打开/关闭/键盘焦点、空数据/不可用状态。未实现项标NOT_IMPLEMENTED，未执行项标NOT_RUN。新的视觉效果若不在契约中，先说明取舍，不让生图中偶然增加的按钮扩大任务。
