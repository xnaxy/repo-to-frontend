# 架构图、逻辑关系和数据图的按图构建

在严格模式遇到架构图、计算树、流程/时序/泳道图或数据可视化时读取。本文件解决“如何完整重建”，验收仍使用 locked-image-reconstruction.md。不能用本项目的坐标、配色、位数或历史图号作为通用默认。

## 先确定视觉信息，而不是先选组件

用三个问题约束方案：图中各形状承担什么角色？哪些线真正表达关系、哪些仅为边框/网格？如果节点文字都在，仍有什么遗漏会让这张图意思不同？

将同一输入留成三份关联但不互相覆盖的记录：

1. **原图观察**：像素坐标、文字、图形、颜色与置信度。按父区域保存；不从被测页面采集。
2. **语义结构**：实体、分组、计算运算符、关系/序列/期间和单位。可见事实、资料证明与推断分开。没有依据的数字不要为画线反推成精确原始数据。
3. **实现计划**：局部坐标系、原生HTML文本/控件、SVG图形、布局约束、路径、绘图区和尺度、DOM映射。计划是待验证的构建输入，不是浏览器实测。

先复核最大区域的占比、边界、同屏关系和共同基线，再在局部坐标系构建图形。禁止把图的外框相似当作图内部相似；标题、图例、轴标签、图主体和面板是不同区域。

## 从原图建立不会只统计已实现内容的清单

先保存 `visual-inventory.md`（可用JSON替代），按原图两遍扫描：

- 空间遍：从上到下、从左到右，逐区列所有可见族，包括微小符号、脚注、轴单位、箭头头部、虚线、分隔符、禁用/选中状态；边界和空白也要记录用途。
- 语义遍：从每个输出逆追输入，从每条系列追每个期间和图例，从每个表头追全部单元格。与第一遍对账，而不是重新抄DOM列表。

每个族记录 `region / family / expected instances / evidence crop / actual IDs / unresolved`。数量来自原图独立观察；清点不清楚标UNKNOWN。比如有三条系列、五个期间并不意味着有十五个点，缺失点必须逐格登记。

关系型图另列每条边；系列型图另列期间×系列表。重复族可用可展开规则，但交付时必须有展开后的稳定ID。未实现项保留在分母中，不能只为已经画出的对象补清单。

人工第二遍应从原图开始，并检查未标注的像素区域。已有 `coverage.complete`、节点数量、OCR列表、自动比对通过都不能替代这一步。清单是覆盖证据索引，并非自动证明“没有遗漏”的机器判定。

## 架构与计算关系的实现

对每个节点记录父分组、类型、矩形/圆/菱形轮廓、文字、局部bbox、对齐线和原图中的层级。分组边界、泳道名称、运算符圆圈不能缩成节点标题的一部分。

对每条关系记录：

| 项 | 必须辨明 |
|---|---|
| 含义 | 读取/写入、计算依赖、等式展开、导航、分组或未知；不可用阅读顺序猜调用方向 |
| 端点 | from/to及实际依附的端口，不能默认所有边都是下边中心→上边中心 |
| 路由 | 原图每个折点/曲线控制点、共享干线和绕行；相交不自动建立连接 |
| 可见性 | 起点/终点箭头、线色/粗细/虚实、透明度、层叠、遮挡、标签位置 |
| 分叉/汇合 | 哪些语义边共享几何段、哪个点是实际连接、是否存在圆点或运算符 |

先摆节点与运算符，再画边；将边坐标绑定到对应节点端口，节点移动后重新计算。绘图层放在正确z序，不让线穿过不应穿过的文字或卡片。每条语义边一个ID；共享干线可以重复路由，但应核对重叠描边是否加深、汇流点是否正确。不可仅在总图上放一条含多个M的路径来代表所有关系。

单个分叉图至少沿每条输入→运算符→输出走完一遍，包括旁路、反馈、条件分支和底部虚线输入。相同公式的另一种树布局仍不是原图。图像本身存在歧义时，记录两个候选解释及证据；不能悄悄补出业务因果。

构建数据与最终绘制分开验证：arrowEnd=true还需实际marker绑定、marker内容和画面中可见箭头；标记坐标落在plot边界时，SVG外框仍须留出原图允许的半径/描边空间，不能裁掉半个点。留边不能通过移动冻结的绘图区或改变尺度实现。只有构建输出的单测，不足以宣布图已完整绘制。

不要默认使用自动布局。Graphviz/Mermaid/图表库可以提供内部能力，但其自动排布、样式和路由不保证原图一致。固定参考优先采用测量后的局部坐标与显式SVG路径；曲线、时间泳道或非矩形端点要用相应实现，不能为了套工具改图。

### 可复用的端口/折点构建

`scripts/visual-geometry.mjs` 的 `buildRelations(nodes, edges)` 是无依赖ES模块。它从已测量的节点bbox、矩形边界归一化端口和显式折点生成独立路径、锚点、箭头起终标志；没有自动布局或避障。

```js
import { buildRelations } from './visual-geometry.mjs';
const nodes = [
  { id: 'source', bbox: [20, 30, 100, 40] },
  { id: 'target', bbox: [220, 110, 100, 40] },
];
const paths = buildRelations(nodes, [{
  id: 'source-target', from: 'source', to: 'target',
  fromPort: [1, 0.5], toPort: [0, 0.5],
  via: [[170, 50], [170, 130]], routing: 'orthogonal', direction: 'directed',
}]);
// 用createElementNS创建path，逐项设置data-r2f-id/from/to和d。
// arrowEnd/arrowStart分别绑定经原图确认的marker；false时不设marker。
```

同一SVG局部坐标系内使用；浏览器采集会转换成视口CSS坐标，不把计划的局部anchors直接写入actual。direction是directed/reverse/bidirectional/undirected；路由为orthogonal或polyline。缺节点、重复ID、内部端口、非有限坐标、零长度线段、正交路由出现斜线会抛错，不能catch后默默漏边。圆/菱形不在矩形边界的端口、曲线与自绘箭头需要自定义适配并实测；不强塞进这个函数。

## 图表从绘图区和尺度开始

每张图明确：图表类型、绘图区bbox、轴方向、线性/对数/分类/时间尺度、domain、ticks及显示字符串、零基线、网格、每条系列颜色/线型/标记、图例顺序与选中状态、数据标签、单位、误差带/目标带、缺口和注释。原图没有图例时也记录“无”，不能按组件默认新增。

| 图形类型 | 复刻易漏点与实现依据 |
|---|---|
| 折线/散点 | 完整期间顺序、缺失断线、孤立点、负/零值、直线/阶梯/曲线、标记半径、轴与图例绑定 |
| 分组/堆叠柱 | 系列内外顺序、柱宽/组距、正负基线、堆叠起止、总计与分项标签、相同数据不能重复求和 |
| 瀑布/利润桥 | 每根柱起点和终点、增减符号与绝对金额分离、总计柱、连接线、标签所在侧；不得因费用已为负又减一次 |
| 饼/环/雷达 | 起始角和方向、扇区顺序/内外半径、角度尺度、标签引线、雷达轴顺序与各轴量纲；不得按默认库样式替代 |
| 热力/矩阵/区间 | 每格行列归属、颜色domain、缺失编码、区间端点、阈值线；不能只有几张相似色块 |

先标绘图区的左上/右下、已知两刻度、一个负/零或缺失点；确认转换后再生成所有标记。轴边缘不是总图边缘。类别轴等距，真实时间轴按间隔；不能混用。像素几何正确和业务数据正确分别验证。

保持原图的图表类型、系列、刻度和可见标签。现有产品的自适应“少数据用柱图、多数据用折线”只能用于已授权的响应式/设计提升，不能在固定参考状态下改图。防碰撞也不能通过隐藏原图标签、移走图例、截字、删系列或全局缩小字体来通过。

`projectSeries({plot:[x,y,w,h],xDomain:[...],yDomain:[bottomValue,topValue]}, observations)` 提供**分类横轴+线性纵轴**坐标。每个observation有唯一id、x类别和有限number或明确null；必须为完整domain逐项提供观测。返回marks、segments、missing和zeroY，缺口拆段，零值保留，domain外数据拒绝而非钳制。每条系列分别调用并保留其ID前缀；绘制长度为1的段时保留点而不捏造连接线。它不计算刻度、不做柱/饼/堆叠/对数/时间轴。超出此范围使用明确的其他实现，不能静默换图。

绘图区、尺度和数值是实现输入，不是参考像素已正确或数据真实的证明。图片只显示线形而没有精确数值时，记录测得的点位及不确定度，直接按图实现其外观；不要为调用数值工具制造假数据。

动态系列的缺失验证要检查最终图形，而非只看表格是否显示“不可计算”。覆盖首个、中间、末尾及全部缺失：各有效段重新起笔，缺口不被实线跨接，孤立点保留，全缺失不出现虚构点。SVG每段应从有效的M命令开始；根据原数组索引决定M/L会在首点缺失时生成无效路径，在中间缺失时错误连线。若原图明确用虚线跨缺口，单独记录这种参考几何，不把虚线插值点当已知数据。

## 同屏状态、文本和交付闭环

原图中同时出现的树、详情和实验表必须同时出现，不能变成“点一下才弹出”的替代实现。先测初始/空态，再测有数据态；内容变多后再检查固定/自动高度、滚动区域和底部是否被遮挡。无参考的新状态仅验证功能与产品约束，不声称按图证明。

文本用自然行/段落/单元格；字号、字体、字距、行高、换行和单位分别调。元素盒不代表字在正确位置，父区宽度正确也不代表文字未溢出。图像墨迹不能直接与Range布局盒比较：独立原设计可证明Range预期时使用工具的textBounds门禁；仅位图时用同尺度裁片、已声明测量类型和视觉复核，保留字体未知。

字体/细线的具体诊断、资源安装和真实字体取证见 [font-and-raster-calibration.md](font-and-raster-calibration.md)。

若字宽/字形成为主要残差，不凭“某字体看着近”批量扩展。先在原图选择一个数字与单位组合、一个中文标题、一个最窄正文行；保留原crop和坐标，测可辨墨迹宽高/基线及其不确定度。在已有可用字体中试有限的合理候选，每次只改字体族或字号/字距中的一个变量，同位置真实截图并比较该行及相邻行。数字和中文允许不同字体，但不能横向拉伸字形或逐字绝对摆放。采用候选前，验证长行、换行、符号、所有数值和单位没有回归；无法确认原字体身份依然UNKNOWN。校准记录为“候选字体/参数→局部证据→保留或否决”，而不是仅给出主观分数。

每个可见输入也属于叶节点：逐项核对 `value/checked/selected`，不能用textContent或抽查两个关键数字代替整组；参考端清单来自原图，实际端来自浏览器。放大截图仍难辨的文字先回看原图和实值，不能把目测误读直接记成业务数据错误。

每批完成后按 `原图对象→清单→实现→当前截图` 和反方向逐项对账，检查几何、拓扑、文字与图表编码四项。保存具体差异，不以平均像素误差抵消漏箭头/单位/标签。共享样式改动后逐页重查受影响族，代表图通过只允许继续实现，不能替代全套验收。

最终逐区域表必须含未测与未实现项；工具PASS_CONTRACT仅支持其合同范围。构建坐标工具、核验工具和独立前向实验的结果分别报告，不把新工具存在当作复刻能力已达标。
