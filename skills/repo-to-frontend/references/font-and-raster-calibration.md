# 字体与细线残差校准

当轮廓已接近、文字或细线仍明显不同，先区分原因，不直接安装一批字体或统一缩小字号。保留原图、当前HTML、截图、浏览器版本、系统、视口、DPR、缩放与文件指纹；所有候选在同一环境比较。这是原图返修实验，不冒称独立盲测。

## 先问三个问题

1. 是缺少字体，还是浏览器没有采用已声明的字体？
2. 是字形不对，还是文字位置、字距、字号、字重或父级排版不对？
3. 改动是否改善全部受影响实例，同时保留相邻单位、按钮、线条和可见输入？

以原图独立选数字与单位、中文标题、密集公式/正文和输入四类样本；记录所有同类消费者作回归组。字号和墨迹高度不是同一概念。字体身份没有来源证明时始终UNKNOWN，即使候选更接近。

“固定几何”是隔离字体变量的实验条件，不证明旧几何正确。若边框/基线已偏离原图，先保存这个事实；字体轮次结束后另开布局轮次，独立测量原图边缘并修正。不可为了保持旧DOM盒测试绿色而保留已知错位，也不可改了位置仍把收益全部归给字体。

## 证实浏览器真正使用的字体

`font-family`是候选列表，`document.fonts.ready`只等待字体加载/布局，`document.fonts.check()`对不存在的字体也可能返回true。它们都不能证明实际字形由某个字体绘制。

Chromium可用 `scripts/audit-fonts.mjs` 的 `auditRenderedFonts(page, probes)`：

```js
import { auditRenderedFonts } from './scripts/audit-fonts.mjs';
const observations = await auditRenderedFonts(page, [
  { id: 'headline', selector: '[data-r2f-id="headline"]' },
  { id: 'amount', selector: '[data-r2f-id="amount"]' },
]);
// 保存observations，并在同一冻结页面状态立即保存截图及其指纹。
```

此函数接受已有Playwright Chromium page，不导航、不写页面、不安装字体。输出CSS声明和浏览器实际报告的familyName、postScriptName、isCustomFont、glyphCount。探针必须唯一匹配；缺失、多匹配、异常、无法取得证据分别记录。它不是完整性或视觉通过门禁。

切换字体或共享样式后，先确认目标computedStyle已更新、等待document.fonts.ready，再等待页面绘制机会后采集（可用连续两次requestAnimationFrame，或实际截图触发绘制），不要把切换前CDP缓存误判为字体缺失。两帧不是所有应用稳定的保证：有动画/异步更新时仍需等待明确目标状态并复采样，报告与截图必须来自同一状态。未核切换时序前不要安装字体或改字体名称。原生控件或不支持的探针仍保持未知。

原生number输入和textarea即使有可见值，某些Chromium环境也返回空字体列表；这时必须保留UNKNOWN/PARTIAL，不能根据相同CSS的text输入已成功就推定它们也已验证。

CDP对父元素可能汇总子树字体，因此 `SUBTREE_NOT_DIRECT_TEXT` 不能给父级某一段文字归因；工具另列子文本元素，只有对应叶节点证据才支持该局部判断。不要累加父子/重叠探针的glyphCount，也不要把glyphCount当字符数量。普通非空文本/数字input和textarea在CDP实际返回字体时记录NATIVE_CONTROL_CDP，读取value而非textContent；这仍不证明原生文字布局盒。空值/占位、密码、select等未支持控件、display:contents文本、伪元素、Shadow DOM、iframe和其他浏览器另取证；工具明确列未覆盖项，不以镜像span冒充原生控件实测。字体文件哈希仍需独立记录，平台字体名称本身不是文件字节证明。

## 安装与携带字体的条件

先查现有字体和实际使用证据。仅在原文件可得、或有限候选有明确字形依据时获取新字体。优先官方项目/发行地址，记录来源、版本或提交、许可和SHA256；确认是否允许网页嵌入/再分发。

独立页面优先项目内 `fonts/` + `@font-face` 的固定资源，使用明确别名、weight/style和可变轴范围，避免依赖某台电脑已安装的字体；不要将商业系统字体随包复制。保留许可。用户确实需要系统安装时再采用该系统的用户级安装流程。

新字体必须以目标页面真实字符测试并经浏览器确认实际使用。字体加载成功也可能因缺字而局部回退。保留加载失败与混合字符反例；离线交付在file入口、断网和无预热缓存的新上下文验证。若用 `local()` 优先来源，需披露其可能绕过包内固定字体。只改字体名或装完字体后不重启/复测浏览器，均不是完成。

## 有限候选，不做盲目穷举

先比较少量合理字体族；再对选定候选分别调字号、字重、字距或原字体支持的宽度轴，一次一个变量。固定原图裁片与位置；查看字形、笔画粗细、数字宽度、基线和相邻行，并保存每一轮保留/否决理由。不得使用字形横向拉伸、逐字定位、截图贴底或放宽阈值伪造一致。

候选字体只在实际改善的族中应用。一个数字行的平均误差下降，不能证明中文标题、所有公式和输入同时更好。检查全部受影响对象，尤其是行内input旁的单位、按钮与父行高度：更换字体可经基线对齐改变相邻元素位置，即便输入本身外框未动。发生联动时修明示的排版原因并单独验证，或者否决候选；不要悄悄移动单位补偿后仍把全部改善归因字体。

固定颜色空间、通道数、alpha处理、区域和阈值；RGB与RGBA平均分不能直接横比，不把统计口径变化当收益。

平均像素误差是诊断之一，不是唯一目标。检查细笔画、数字辨识、换行、截断、遮挡与完整性。背景纹理会影响大量像素；分别报告背景、文字、边线区域的差异，不删除不利区域或用整体均值抵消关键内容退化。未确认字形来源时，只能说某样本更接近。

## 细线、边框和抗锯齿

字体实验以外另校准边线。先在原图选不含文字、箭头、交叉点的直线段，检查相邻物理像素行/列的颜色和覆盖；同方向不同位置各取样，避免由一个点推全图。明确CSS坐标、SVG局部坐标、变换和DPR之间的关系。

线条可能落在小数坐标。不要默认所有坐标取整数，也不要全局加0.5px：所需位置取决于DPR、线宽、变换和原图。只修改有证据的段并复验其折点、端口、箭头和周围对象；原图同一水平线的轻微不规则也不能自动解释为浏览器错误。不要用全局 `crispEdges` 把曲线/箭头锯齿化。

先保持线宽/颜色不变校准位置，再分别试线宽/颜色；原图含压缩、纸张纹理或生成噪声时保留残差说明。合成背景纹理若只是降低平均分而不能恢复实际细节，不作为修复完成证据。

## 完成标准

记录基线、每次尝试、否决和最终版本；内容/数据/关系不变另验，样本和全部消费者的视觉差异另验。组合字体与几何两项改动后重新截图测试，不能简单相加它们的独立收益。将可迁移方法写入Skill，具体坐标和字体选择留在案例目录。

原始字体/矢量素材/绘制环境缺失时可以持续降低误差，但不能承诺仅安装字体就恢复所有像素。完成一次优化与严格1:1通过是不同结论，逐区域保留剩余差异。
