# 真实图片作为视觉输入

## 生成

先探测当前工具和已安装技能。可用 `imagegen` 时读取其指引：通常内置图片工具不需要用户 API 密钥；明确指定 CLI/API/model 路径时，才按它的路由使用现有 CLI。不要因缺少 `OPENAI_API_KEY` 就断言所有图片能力不可用，也不要另建付费请求服务。

未指定时默认请求 `gpt-image-2`，用户明确指定其他可用模型则以用户为准。工具能选择时显式选择；工具不能显示模型身份时记录实际 requestedModel、`confirmedModel: null`，不能用提示词中写了模型名充当证明。若用户要求严格确认模型，且没有可确认路径，交付已完成阶段并标记 `BLOCKED_IMAGE_MODEL`。不要未经授权改用其他模型。API 参数、模型可用性和支持尺寸需查当前官方资料，而不是把旧快照永久写死。

仓库任务先按 [project-grounding.md](project-grounding.md) 完成受影响页面的契约准入。提示词从同一设计简报与能力合同生成，包含：

- 用途：用户指定的解释页面或真实产品前端，明确静态解释/模拟/真实对接，不默认生成工具仪表盘或设备样机。
- 阅读目标与章节顺序，核心 C 编号对应的具体内容。
- 视口/纵横比、网格、留白、字体层级、配色、关系图与关键组件。
- 精确标题、字段与必要正文；可变长正文允许真实实现时流动排版，但每项核心功能、入口与必要结果态必须先在图集中有参考，不能留到HTML补漏。
- 必须保留的关系方向；不许虚构指标、标志、事实，不加透视设备边框。
- 当前状态与所有可点击项的动作、具体结果内容、目标图/状态及返回规则。要求在图像中明确表现按钮和结果区域，并按约定呈现交互注释；明显改变布局的结果态独立生图，见interaction-contract.md。

单图任务默认一张主要页面参考；整套图表按 chart-suite.md 的清单逐图执行。后端产品按[图片功能闭环](image-contract-loop.md)完整审查图集，汇总全部问题后按原风格修图并重新全检，零未决后才复刻；不以修图次数判成功。其他独立视觉任务按其用户范围修订，失败保留真实状态。调用超时且结果不确定时先查已有结果，不能盲目重发造成重复费用。

保存真实返回图片、提示词、工具模式、可得的模型/请求标识和图片哈希。图片在工具默认目录时复制到当前输出，记录实际文件路径。使用工具实际支持的参数，不猜测本地路径或响应字段。

官方资料（仅在需要当前 API/模型细节时读取）：

- [gpt-image-2 模型](https://developers.openai.com/api/docs/models/gpt-image-2)
- [图片生成指南](https://developers.openai.com/api/docs/guides/image-generation)

## 看图提取视觉规格

在写前端视觉代码之前，用当前视觉工具打开保存的那张图片；不可用时明确阻塞视觉提取。记录实际可见的区块比例、对齐、间距、字体层级、颜色、边框、纹理和插图。把观察与推断的交互分开：静态图片不能证明按钮实际行为。

在 `05-visual-spec.md` 中附图片路径/哈希、视口假设、区块与 C 编号映射；独立图片任务可用用户内容ID，不虚构仓库证据。用户只提供外部图时也做同样的检查。后端产品若图片误生成数字或改变关系，先按图片功能闭环修图，例外账本只记录问题而不放行。其他外部图保真任务若有冲突，以已验证文稿为准并按用户约束进入节点级例外账本；纠正参考须另存新版本，旧图仍保留。不把错误视觉复制成事实，也不把纠错后版本称为旧图完全一致。

分清设计提升与定稿复刻模式：参考锁定后，不自行美化或更换配色、字体、密度、素材；用户后来解除约束时记录切换到设计提升，按design-quality.md重排，不继续强制固定坐标。锁定模式每个区域记录原图坐标 bbox、父子关系、对应 DOM、列宽/间距、字体/字重/行高/换行、颜色/边框/圆角及素材来源；量测值、估计值、未知分开。裁片保留全图坐标和角色，不当新页面。所有模式的数据图都记录原始数值、单位、刻度、图例、连线方向与编码，不能用外观相似替代数据正确。

## 复刻与验收

所有按选定图片实现的任务先执行[按图实现的缺省合同](reference-fidelity.md)，即使用户没有说“严格”。reference模式也保护结构和首屏信息；只有逐像素门槛限定在strict模式。不得以两轮修正结束、差异已披露或功能通过代替视觉目标达成。

仓库任务使用 `05-codex-implementation-prompt.md` 交接实际机制、接口、数据和状态；新上下文必须读到对应事实包，不能靠“按上文实现”。先将图中数据/控件反查契约再构建；视觉忠实不能要求实现不存在的后端能力。详见project-grounding.md。

复用目标已有栈和设计约束；独立视觉样例优先自包含 HTML/CSS/JS，复杂应用按需使用框架。只创建展示该仓库所需的前端，不安装 screenshot-to-code/OpenUI 整个平台来完成一个页面，除非它已是用户选定工具。

将布局拆为真实组件和可访问文本；需要的插图可复用图片资产，但整页一张大图不算前端复刻。实现简报约定的交互；文案及关联证据随 C 编号保留。窄屏按阅读顺序重排，而不是整体缩小桌面截图。

素材优先级：用户/仓库原素材 → 可独立提取且可合法使用的图中素材 → 披露的替代。允许原始品牌标志、独立功能图标、照片与证据图片，保留许可、替代文本及角色映射；禁止把整页截图、文字/表格裁片充作可操作页面。文字、按钮、表格和关系图主体用 DOM/SVG/数据实现。重新生成资产可能改变像素，不默认重绘已有可用资产。先容器/网格与大色块，再文字与换行、素材位置、局部间距、细节。

截图合同记录原图像素、CSS 视口、DPR、缩放、浏览器、主题、滚动位置和固定数据。像素尺寸不能无条件当 CSS 尺寸；未知时采用明确假设并记录实际环境。等待字体就绪、图片解码且 naturalWidth>0，禁用影响对照的动画/随机时间。缺图、空白图和致命运行错误不得计为通过。工具不能控制尺寸/DPR或导出原图时，标记该项 NOT_RUN/受限，不能绕过权限或伪称标准化。

严格比较先验证原始图与截图像素尺寸相同且裁切规则相同；不同则修正截图环境，不静默缩放。诊断用缩放图必须另存并标明，不作为严格验收依据。记录实际算法、区域、预处理及容差；退出 0 仅表示计算成功。MAE、CLIP、模型裁判分数都不是“还原百分比”，大面积背景会掩盖局部问题。

运行最相关测试和生产构建；启动浏览器，至少检查一个桌面与一个窄屏尺寸、关键交互、错误日志、横向溢出。严格模式按locked-image-reconstruction.md与strict-replica-tools.md执行失败关卡；修复预算不足时保留FAIL/BLOCKED，不套用“两轮后通过”。非严格模式默认最多两轮有针对性的视觉修正，未达目标如实列差异。没有修改授权时只报告，不进入修复循环。

每轮同时看原图、当前截图、相同区域裁片与现有代码，选最大的三项可见差异，记录区域/事实/预期与实际/拟改属性/复验结果。只局部修改并复查全图回归。边缘偏移可先以 2 CSS px 作为修复触发值，但这只是可调整的工程起点，不是科学通用阈值；不能为通过修改参考、阈值或掩码。

分别报告语义一致性、视觉相似性、运行/交互结果。不能凭主观观感造“95%还原度”，也不能把构建成功等同于浏览器验收。若浏览器能力缺失，保留源码和构建结果，浏览器检查记为 `NOT_RUN`。

交付原图、最终截图、可比条件、分区差异表及必要的并排/叠图。语义纠错与原图偏差另列，不把纠正后的文本称为逐像素相同。全部已约定门槛实际满足才可标通过；仍有残差则写“待审核/部分达标”。用户亲自接受后才记为用户已接受。两个样例仅证明这两个输入的表现，不证明任意图片都能 1:1。
