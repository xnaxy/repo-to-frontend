# 可选的独立子代理对抗性审查

本协议覆盖 analyze、brief、image、build、verify 五阶段，包括单独调用。它是 Codex 执行规则，不是后台服务或不可绕过的运行时锁。`independentReview.enabled` 默认 false；关闭只免除独立子代理审查，不免除主代理自检、能力合同、图片审核、测试、浏览器和真实联调。

## 开关与继承

- 用户说“开启独立子代理审查/每阶段让subagent对抗审查”时设 true；“关闭独立子代理审查”设 false，并保存决定依据。总入口统一应用于本次所有已选阶段，独立阶段调用同样读取。
- 新任务无设置且无待继承决定时才默认 false。同任务/同输出目录继承；“继续/自主完成”不关闭已启用设置。状态丢失时从本任务用户决定恢复，不借缺失文件复位。其他项目不继承。
- “这次审查一下方案”仅授权本次审查，不替以后所有项目开启。独立验收入口表示验收职责分离，不自动等于新代理；只有确实派发新上下文并完成才记录独立审查。
- 与 `imageReview` 正交：关闭图片审核不关闭本开关；代理通过不等于用户批准图片。中途开启从当前阶段生效，核验所消费的上游证据；未实际审查的历史阶段记 NOT_RUN，不自动重跑未选阶段。若发现上游阻断问题，停止受影响交接并按既有授权修正或报告。

## 每阶段审查时点

先完成该阶段必要工作和主代理自验，冻结当前输入/产物，再在交接或声明阶段完成前派发。审查期间主代理可做不修改本轮输入的独立工作；不得让下游提前消费尚未通过的受影响产物。

| 阶段 | 审查者必须对照的原始依据 | 重点反例 |
|---|---|---|
| analyze | 原始入口/注册/部署清单、源码、配置、测试与能力台账 | 漏worker/插件；死代码当能力；文档与激活配置不一致 |
| brief | 独立覆盖台账、能力合同、文稿/页面/交互映射 | 只审已选C编号导致漏能力；数据库字段当接口；异步受理当完成 |
| image | 实际发送prompt、实际图片、允许字段/动作/状态合同 | 新增取消/进度/导出；关系反向；样例性质丢失；结果态缺失 |
| build | 原图、事实包、代码、实际测试/浏览器/联调证据 | 只看prompt没看图；模拟冒充真实；旧响应覆盖选择；几何正确但数据错误 |
| verify | 原始参考、合同、实际交付、原始采集及报告 | 自生成预期、漏区域、旧截图、新合同配旧报告；PASS_CONTRACT冒充完整成功 |

image 阶段必须有审查者实际看图记录；没有视觉能力只能返回受限，不以文件名或prompt代替。verify 审查现有检查证据与必要抽查，不递归创建“审查审查者”的新阶段。

## 隔离和返回

使用可用的 Codex 子代理能力，创建全新上下文（支持时 `fork_turns="none"`），不得复用该产物的作者或已受作者推理影响的上下文冒称独立。只传用户目标、范围/权限、相关规则路径及冻结输入清单，不传作者的推理、自评分数或期望“通过”的答案。报告作为待审对象时可读，不能当真值。模型沿用当前配置，除非用户另有指定。

审查者可按允许范围自行只读追踪源码与原始证据，不能仅阅读作者摘要。它不得修改项目、合同、状态、阈值或参考图，不自行安装依赖、启动变更型服务、提交业务写操作或再派发子代理；必要验证缺口交回主代理。共享文件系统不是权限沙箱，隔离指上下文和执行约束，不声称物理隔离。

只回传紧凑结果：结论、实际审查范围、问题ID/严重程度、证据路径/符号或图像区域、可复现反例、影响、最小建议、未审范围。没有发现也说明检查了什么。原始文件全文、命令长输出和思考过程不回填主上下文；主代理仅保留这份答案和必要定位。这里不承诺删除平台保存的子代理历史。

## 记录、失效与收口

主代理保存 `reviews/<stage>/rN.md` 与对应输入清单。每轮记录 stage、用户目标/范围/交付模式、上游合同、当前产物及本协议的实际路径和 SHA256、审查者ID、执行方式、结论和问题处置。实现阶段包含可恢复代码基线/补丁或逐文件清单、测试/截图对应版本；不只哈希一个入口HTML。

在 `run-state.json` 合并 `independentReview: {enabled:false, decisionEvidence:null, stages:{}}`，保留其他字段。每阶段记录 inputManifest、inputDigest、reviewerId、report、status、executionStatus、findings；digest基于按逻辑ID排序的文件哈希以及范围/模式/规则摘要，路径仅移动且内容/逻辑ID不变可复用，重新核对路径。缺少可读取证据不能填 passed。

状态：disabled、pending、passed、changes_requested、blocked、stale、NOT_RUN。passed仅表示本版本本范围未有未决阻断问题，不代表阶段其他关卡通过。已确认错误能力、漏关键旅程、失真数据、无证据成功声明或会改变承诺的未知阻断交接；主代理逐项依据原始证据接受/反驳意见，保留处理理由，不盲从代理。分歧未解决时保持 blocked；非阻断建议记录理由后可继续。

相关源码/配置/合同/prompt/图片/实现/验收证据或审查规则改变，使相关审查 stale；下次交接前重核。无关变化注明依据后不重复审查。用户明确关闭仅免除后续代理关卡，不抹掉已经发现的事实错误。

默认每阶段一轮完整审查，修正后至多一轮针对变更及相邻影响的复核。此预算防止循环，不能用耗尽预算判通过；仍有阻断问题如实交付限制。没有可用子代理时stage审查status=blocked、executionStatus=NOT_RUN；已尝试调度失败为blocked/FAILED；审查已返回但必要文件/视觉不可读为blocked/COMPLETED并保留缺口。历史未要求审查阶段的status=NOT_RUN与当前阻断不同。不得用主代理自审顶替，也不擅自转成新用户任务。已授权的无关工作继续；有现成可用槽位时直接派发，不重复询问用户。

## 最小验证情境

默认关闭；开启后独立阶段继承；仅调用verify但未开关；同路径换图/改合同；禁用图片审核但子代理审查开启；开启图片审核但子代理通过尚无人批准；代理不可用；中途开启；只读审查发现需修改实现；修复后旧报告；两轮后仍有阻断问题。分别记录实际决策，不能以文档含有关键词代替前向情境结果。
