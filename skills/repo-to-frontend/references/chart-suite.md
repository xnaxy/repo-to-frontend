# 整套图表：共享语义，不共享幻觉

当用户要完整项目图集，先按理解任务选图：架构总览回答职责与边界；请求时序回答一次运行的先后/并发；数据流回答字段与状态如何变化。必要时加失败/恢复或扩展视图，不为凑数量加入无证据的图。

复杂项目即使用户没有指定张数，也按核心问题分图，解释为什么拆分；简单项目可单图。每张图应回答不同问题或呈现必要的交互结果态，而不是更换皮肤。为图集另建导航/状态关系，记录进入控件、携带筛选、返回来源；不能用教学前置图代替实际导航实现。每张图和关键结果态均有真实参考与对应可达HTML视图，逐项核验，禁止以总览图成功代替整套完成。

在 `chart-suite.json` 中记录共享术语、节点 ID、关系 ID/type/from/to/evidence、准确标签和设计标记（颜色的语义、字体层级、边框、箭头、网格）。每张图有 id、读者问题、前置图、内容 ID、包含的关系、画布比例、参考图、提示词和阶段状态。图集覆盖已约定的核心问题即可，不宣称穷尽仓库。

示例：overview 显示 N01 入口与 N02 处理器的职责；sequence 复用 N01/N02 展示调用 R01；dataflow 展示 R01 传递的数据结构。章节阅读顺序不可冒充 R01 的运行方向；同一节点跨图名称和颜色不漂移。图中数字、单位、刻度、图例与源数据单独核验，装饰不改变意义。

先生成视觉锚点图并查看结果，再按工具支持的参考图机制生成其他图，明确“风格参考而非编辑目标”。重复共享标记及必须保持的关系，每张图只增加自己的信息。一次调用只生成一张可独立使用的图，不用巨型拼图降低文字可读性；用户明确要一张多面板图则遵循。

采用“内容契约 → 视觉构图 → 不变量”的提示词结构，精确引用标签和必要正文，长正文的可变内容可在实现中展开，但全部核心功能与结果态先在图集具有明确入口和布局参考。不要照搬无证据的提示词字数上限。逐图保存实际图片、模型身份已知/未知、哈希和提示词，检查重复/缺失/反向关系及跨图术语一致性。未知、失败、未生成分别保留状态，不能因第一张成功把全套标成完成。

有控件时结合interaction-contract.md，在每图prompt中加入动作→结果→目标状态的明确说明。图集验收同时检查关系覆盖和交互覆盖：稳定ID可追踪到叙述、图像、DOM和测试动作；同一企业/年度的数字与来源跨图一致。

先按[图片功能闭环](image-contract-loop.md)修正后端产品图集语义错误并重新全检，再锁定最终参考复刻，不能等HTML纠错。外部旧图明确保真任务如需语义纠错，记录区域、旧值、新值与依据并遵守用户目标，不称原图完全一致。用户提供合成场景时明确标注 simulated，不为其编造仓库提交或证据。

“原始图片 + 语义纠错清单”仅限用户明确要求保留外部旧图等独立任务；不适用于后端产品生图闭环。该流程中纠错清单必须反馈图像工具，修正图实际通过才准入，不能以清单替代图片修复。
